## Research questions

1. On a narrow arithmetic task, how much truthful guidance is needed for a
   checkpoint to correct a natural wrong answer while preserving correct ones?
2. Before a hint or decision is generated, can a simple probe distinguish
   initially correct solutions from natural wrong solutions in frozen model
   representations?

The first question measures **assisted repair**. A hint that says an answer is
wrong gives away the KEEP/REVISE label; success under that condition does not
demonstrate independent error detection. The second question examines signal
availability, not whether the model uses that signal causally.

## Narrow task and source rules

Use short, multi-step arithmetic word problems for which the final numeric
answer and each declared calculation step can be checked deterministically.
Natural wrong answers must be generated by the common original solver. Do not
write wrong answers by hand, transplant answers between problems, or select
errors based on candidate model performance.

Before seeing Phase 5 review or probe outcomes, fix an eligibility rule for
step parsing. If a step cannot be located and checked reliably, exclude that
source from the location/type analysis by the frozen rule and report coverage.
Do not fill a failed bucket with fabricated errors or post hoc prompt edits.

Deduplicate by normalized question and source identifier. Exclude all known
Phase 1–4 training, development, probing, and confirmation sources. A Phase 4
confirmation source remains excluded even though it was unopened. Keep a
machine-readable exclusion inventory and hashes. If this source audit cannot
be completed, do not claim a fresh or protected test.

Tentative maximum: 480 eligible sources, balanced by initial correctness, with
240 probe-train, 80 probe-dev and 160 protected probe-test sources. The same
source split applies to review generation and probing; a source never moves
between splits. Freeze an exact selection order and seed before inspecting
candidate behavior. If natural-error or step-localization coverage is too low,
report infeasibility rather than lowering the eligibility rule after test
inspection.

## Checkpoint and prompt comparison

Use the original `Kxck/Self_Correction_v1`, Phase 4 warm-start V2, and Phase 4
correction SFT V3. Verify hashes and load each adapter on its recorded parent
checkpoint. Keep the initial answer, problem, decoding budget, and response
contract fixed across checkpoints and hint conditions. Review prompts contain
no reference answer, complete correction, verifier trace, or hidden test.

Predefine these paired conditions:

| Condition | Wrong initial answer | Correct initial answer |
|---|---|---|
| Neutral | General check request | Same general check request |
| Status | Truthful statement that an error exists | Truthful statement that no error was found |
| Location | Identify the step to check, without correction | Identify a valid step to check, without asserting an error |
| Type | Identify the error class at that step, without correction | Name the arithmetic property checked at a valid step |

The location and type conditions also disclose that the wrong answer has been
flagged. Report their gain over the status condition as the added value of
localization. Log the exact hint shown to the model. Hints must be verified by
a deterministic rule or independent annotation performed without looking at
the reviewing model's outcome. Ambiguous hints are excluded by the frozen
eligibility rule.

The primary behavioral outcomes are final verified accuracy, wrong-to-correct
fixes, correct-to-wrong harms, strict output validity, and paired accuracy
changes from neutral to each hint condition. Report them per checkpoint and
correctness bucket. The protected result uses a source-level paired interval;
generation seeds on the same source are repeated measurements. Do not choose
the best seed, checkpoint, or hint after viewing protected results.

## Representation probe

Capture a fixed hidden-state position after the model has read the problem and
initial answer, before any hint or KEEP/REVISE output. Probe each checkpoint
separately. Use frozen weights and fit only a regularized linear classifier on
probe-train; choose layer and regularization on probe-dev. Evaluate the chosen
probe once on protected probe-test. Match correct and wrong groups by source
family, answer length, step count, and formatting where feasible, and report
unmatched properties. Fit controls on simple surface features and shuffled
labels. Store layer/position definitions and all train/dev/test source IDs.

Primary probe metric is balanced accuracy; report uncertainty by source,
REVISE and KEEP recall, and performance on initially plausible wrong answers.
A probe above controls suggests accessible information. It does not prove the
model can use that information for correction. A null result means this probe
did not find a usable signal; it does not prove no signal exists.

## Decisions and limits

No checkpoint is promoted on pilot loss, guided accuracy, or a probe result
alone. A useful assisted-repair result requires more fixes without a material
increase in harms or contract failures on the protected comparison. A useful
autonomous-detection lead requires a pre-hint probe that beats controls on
source-disjoint protected data and a separate behavioral test showing the
signal can guide decisions. If either gate fails, preserve the negative result.

Protected test rows are opened once after prompts, hint rules, layer choice,
hyperparameters, metrics and stop rules are frozen. No protected output may be
used for training, sample selection, prompt tuning or a second selection pass.
Any later intervention needs a new phase or separately registered experiment.
